## 1. المراحل المكتملة (Completed Milestones)

### ✅ أ. التأسيس الهندسي ومحرك العملات والواجهات (المراحل الست الأولى)
- عزل أعطال الصفحات عبر `FeatureErrorBoundary` وتقسيم الحزم عبر `React.lazy` و`manualChunks` في `vite.config.ts`.
- بناء المحرك المالي الموحّد `src/lib/money-engine.ts` بدقة 8 خانات عشرية على العملة المرجعية `USD`، مع `use-money.tsx` و`MoneyInput.tsx` ولقطة سعر الصرف التاريخية `CurrencySnapshot`.
- تنظيف الأكواد والأسعار الثابتة للعملات (`TRY`/`SYP`) وتفعيل الوضع الخفيف للأجهزة الضعيفة (`src/lib/performance-mode.ts`).
- توحيد النوافذ الحوارية ومقياس الخط النسبي (`rem`) وشبكات الإحصائيات المتجاوبة (`grid-cols-2 sm:grid-cols-4`).

### ✅ ب. التعريب الكامل ثنائي اللغة (`AR / EN`) وتطابق RTL/LTR
- تفعيل اللغتين العربية والإنجليزية (`ENABLED_LANGUAGE_CODES = ['ar', 'en']` في `src/lib/i18n.ts`) مع تحميل كسول لملف `en.ts`.
- تعريب كامل للشاشات الأساسية والثانوية، وتطابق مفاتيح `src/lib/locales/ar.ts` و`src/lib/locales/en.ts`، وضبط اتجاه RTL/LTR ومحاذاتها (بدءاً من `v1.5.257+`).

### ✅ ج. إصلاحات المزامنة السحابية والعمل دون إنترنت (Sync Hardening)
- إصلاح دوال قاعدة البيانات وRPC وEdge Functions وتوحيد `CloudSyncProvider` وفحص الشبكة والتراخيص.
- تنظيف قوائم الأعمدة المسموحة (`TABLE_ALLOWED_COLUMNS`) لضمان عدم فشل المزامنة بسبب أعمدة غير مطابقة.
- إصلاح `removeFromQueue` في طابور المزامنة (`src/lib/sync-queue.ts`) لتصفير أعلام الانتظار (`pending`) بدقة ومنع تعليق العناصر.

### ✅ د. حزم التدقيق المحاسبي الخمس (Accounting Audit — Packages 1–5)
تم تطبيق والتحقق من 5 حزم Migrations إنتاجية على `bwlqfxfvchjvehnbvwaz` مع تحديث 5 ملفات سحابية (`src/lib/cloud/*`) واجتياز **32/32** اختبار E2E محاسبي وأمني:
1. **الحزمة 1 (`20261123010000_pkg1_refunds_drawer_and_digital.sql`):** إحكام المرتجعات وحركة درج الصندوق والمبيعات الرقمية.
2. **الحزمة 2 (`20261123020000_pkg2_purchases_valuation_and_drawer.sql`):** إحكام المشتريات والمتوسط المرجح للتكلفة (`WAC`) وربطها بالصندوق.
3. **الحزمة 3 (`20261123030000_pkg3_debts_expenses_and_fx_lock.sql`):** إحكام الديون والمصاريف وقفل أسعار الصرف التاريخية.
4. **الحزمة 4 (`20261123040000_pkg4_periods_partners_and_locks.sql`):** حماية الفترات المحاسبية وتوزيع أرباح الشركاء (`pending_profit` → `confirmed_profit`) وحل تضارب الأقفال (`AB-BA deadlock`).
5. **الحزمة 5 (`20261123050000_pkg5_data_integrity_and_fk_hardening.sql`):** تعزيز سلامة البيانات وربط `debt_payments.shift_id` بمفتاح خارجي (`FK`).

### ✅ هـ. حزمة الأداء والتوثيق الهندسي الدائم
- تفعيل طبقات الكاش (`NativeSWRCache` + SQLite/IndexedDB + React Query)، والخطوط المحلية، والتحميل الكسول للصور (`ProductImage.tsx`).
- اعتماد المرجعيات الهندسية الدائمة في `docs/speed-rules.md` و`docs/design.md` و`docs/plan.md`.

## 2. المرحلة التالية (Next — Active Priorities)

### 🔜 الأولوية 1: تفعيل Sentry لتتبع أعطال العملاء (Client Error Telemetry)
- **الهدف:** رصد أعطال الأجهزة الميدانية (Android وWindows) تلقائياً مع السياق الكامل دون انتظار بلاغات يدوية.
- **نطاق التنفيذ:**
  - دمج `@sentry/react` وتهيئته في نقطة الدخول مع ربطه بمكوّن `FeatureErrorBoundary` لالتقاط أخطاء React و`unhandledrejection`.
  - تمرير البيانات الوصفية الآمنة فقط: `release` (من `version.json`)، `environment` (`production` / `staging`)، `platform` (`android` / `windows`)، ودور المستخدم.
  - تطبيق `beforeSend` لتنقية أي بيانات حساسة (التوكنات، كلمات المرور، أرقام الهواتف، وتفاصيل المبالغ المالية) قبل الإرسال.
  - تفعيل رفع Source Maps ضمن مسار البناء الإنتاجي لقراءة Stack Traces بدقة.
- **معيار القبول:** تسجيل خطأ تجريبي بنجاح من بيئة Android وWindows بـ Stack Trace مقروء وخالٍ من أي PII.

### 🔜 الأولوية 2: توسيع اختبارات Playwright E2E
- **الهدف:** رفع التغطية الآلية لمنع أي تراجع (Regression) في التدفقات المالية والمزامنة والتعريب قبل كل إصدار.
- **الأساس القائم:** `npm run e2e` (`scripts/e2e/flowpos-e2e.mjs`) و`npm run e2e:stress` (`scripts/e2e/flowpos-stress.mjs`).
- **السيناريوهات المطلوب إضافتها:**
  1. **التدفقات المحاسبية (الحزم 1–5):** البيع النقدي، البيع بالدين، السداد الجزئي والكلي وتحوّل ربح الشريك من `pending` إلى `confirmed`، المرتجع الكلي والجزئي، والمشتريات مع التحقق من `WAC` وعدم نزول المخزون تحت الصفر.
  2. **المزامنة والعمل دون إنترنت:** محاكاة قطع الشبكة (`offline`)، تنفيذ عمليات بيع وتعديل، ثم استعادة الشبكة والتحقق من تفريغ `sync-queue` وتطابق الأرصدة دون تكرار (`idempotency`).
  3. **جودة الواجهة والتعريب (`AR ↔ EN`):** تبديل اللغة والوضع النهاري/الليلي والتأكد من غياب مفاتيح الترجمة المفقودة أو خروج النوافذ عن الشاشة (`overflow`) على أبعاد الهاتف وسطح المكتب.
  4. **عزل الصلاحيات (`RLS`):** التحقق من تقييد حساب `cashier` ببيانات `owner_id` وصفحات `allowed_pages`.
- **معيار القبول:** نجاح جميع سيناريوهات E2E برمز خروج `0` ضمن دورة التحقق قبل البناء.

### 🔜 الأولوية 3: بناء وإطلاق إصدارات Android وWindows
- **إصدار Android (`com.posflow.app` — Capacitor 8):**
  - تحديث الإصدار (`npm run version:bump`) وبناء الأصول (`npm run build` = 0) ثم مزامنة Capacitor (`npx cap sync android`).
  - اختبار ميداني على جهاز حقيقي: زمن الإقلاع البارد (`< 1.5s`)، قاعدة SQLite المحلية، الكاميرا وماسح الباركود (`@capacitor-mlkit/barcode-scanning`)، الطباعة الحرارية، والعمل دون إنترنت.
  - توليد حزمة APK / AAB موقّعة ورفعها عبر مسار الإصدارات.
- **إصدار Windows (Electron):**
  - بناء النسخة المثبّتة والمحمولة عبر `npm run build:electron` و`npm run electron:build:portable` (وفق `ELECTRON_BUILD.md`).
  - اختبار التخزين عبر `IndexedDB`، الطباعة الحرارية/A4، اختصارات لوحة المفاتيح، وتحديث التطبيق.
- **بروتوكول النشر الآمن (`PROJECT_RULES.md` #3 و#6):**
  - جميع التعديلات تُدفع وتُختبر أولاً على فرع `event-or-artifact`.
  - الدمج في `main` يتم حصراً بعد موافقة المالك الصريحة ونجاح `npm run build` (Exit code `0`) واختبارات E2E.
