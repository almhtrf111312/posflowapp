# دليل التصميم الموحّد — PosFlow App (Android & Windows)

> **نطاق التطبيق:** موجه حصراً لمنصتَي **Android** (هواتف، تابلت، أجهزة POS لمسية عبر Capacitor 8) و **Windows** (سطح مكتب وأجهزة كاشير عبر Electron). **لا يشمل تطبيق ويب عام.**  
> **التوافق المرجعي:** يلتزم بمعايير `AGENTS.md` ورموز التصميم الفعلية في `src/index.css` و`tailwind.config.ts` و`src/fonts.css`.

---

## 1. نظام الألوان (الوضع الليلي والنهاري)

الوضع الليلي (`:root` / `.dark`) هو الوضع الافتراضي، والوضع النهاري يُفعَّل عبر الصنف `.light`. **يُمنع كتابة ألوان Hex عشوائية داخل المكونات**؛ تُستخدم رموز Tailwind الدلالية فقط (`bg-background`, `bg-card`, `text-foreground`, `bg-primary`, ...).

| الرمز الدلالي (CSS Token) | الاستخدام | الوضع الليلي (`.dark` / `:root`) | الوضع النهاري (`.light`) |
| :--- | :--- | :--- | :--- |
| `--background` | خلفية الشاشة الرئيسية | `hsl(222 47% 6%)` | `hsl(220 20% 97%)` |
| `--foreground` | النص الأساسي | `hsl(210 40% 98%)` | `hsl(222 47% 11%)` |
| `--card` | خلفية البطاقات والحاويات | `hsl(222 47% 8%)` | `hsl(0 0% 100%)` |
| `--popover` | القوائم المنبثقة والحوارات | `hsl(222 47% 10%)` | `hsl(0 0% 100%)` |
| `--primary` | اللون الأساسي (أزرار الإجراء والمال — Emerald) | `hsl(160 84% 39%)` | `hsl(160 84% 32%)` |
| `--secondary` | الخلفيات الثانوية والأزرار المساعدة | `hsl(215 28% 17%)` | `hsl(214 18% 90%)` |
| `--muted` / `--muted-foreground` | التسميات الثانوية والحالات الخاملة | `215 28% 14%` / `215 20% 55%` | `220 14% 92%` / `215 16% 40%` |
| `--accent` | التمييز التفاعلي (Teal) | `hsl(173 80% 40%)` | `hsl(173 80% 32%)` |
| `--success` | تأكيد البيع والربح والمدفوع | `hsl(142 76% 36%)` | `hsl(142 76% 32%)` |
| `--warning` | تنبيهات المخزون المنخفض والديون المعلقة | `hsl(38 92% 50%)` | `hsl(38 92% 46%)` |
| `--destructive` | الإلغاء والمرتجع والعجز المالي | `hsl(0 72% 51%)` | `hsl(0 72% 48%)` |
| `--info` | الإشعارات والمزامنة والمعلومات | `hsl(217 91% 60%)` | `hsl(217 91% 52%)` |

| `--pos-grid` / `--pos-item` / `--pos-cart` | سطح نقطة البيع وبطاقات المنتجات والسلة | `222 47% 9%` / `11%` / `8%` | `220 16% 95%` / `0 0% 100%` / `100%` |

- **الثيمات الإضافية المدعومة:** `theme-ocean` (أزرق) و`theme-sunset` (برتقالي) و`theme-flowglass` / `theme-xiaomi`، وجميعها تُعيد تعريف `--primary` و`--accent` و`--pos-total` دون كسر الألوان الدلالية (`success`, `warning`, `destructive`).

## 2. الهندسة البصرية وأشكال `Squircle`

- **تدرج انحناء الزوايا:**
  - الوضع القياسي: `--radius: 0.75rem` (`12px`) مع تدرج `rounded-lg` (`var(--radius)`), `rounded-md` (`calc(var(--radius) - 2px)`), `rounded-sm` (`calc(var(--radius) - 4px)`).
  - نمط `Squircle` (`.theme-flowglass` / `.theme-xiaomi`): `--radius: 1.25rem` (`20px`)، و`rounded-xl` = `1.15rem` للبطاقات والأزرار الكبرى، و`rounded-2xl` للحاويات الرئيسية ولوحة السلة.
- **الاتساق البصري:**
  - تبقى زوايا البطاقات الداخلية أصغر قليلاً من الحاوية الأم (`R_inner = R_outer - padding`) لمنع التباين الهندسي الحاد.
  - في جداول التقارير الكثيفة على Windows، يُستخدم نصف قطر معتدل (`rounded-lg`) للحفاظ على مساحة القراءة.
- **التوافق مع الوضع الخفيف (`Lite Mode`):**
  - تأثيرات الزجاج والتمويه (`backdrop-filter`, `--blur-intensity: 20px`) تعمل في الوضع الكامل فقط، وتُعطَّل تلقائياً في `Lite Mode` (`src/lib/performance-mode.ts`) مع استبدالها بخلفيات صلبة واضحة التباين (`bg-card`) لضمان `60 FPS` على أجهزة Android المتوسطة والضعيفة.

## 3. الطباعة والأرقام المالية (`tabular-nums` + عزل `dir="ltr"`)

### 3.1 الخطوط الموحّدة (`src/fonts.css` & `tailwind.config.ts`)
- الخط الأساسي للواجهة: `'Inter Digits', var(--app-font-family), sans-serif` حيث يوفّر `Inter Digits` أرقاماً غربية واضحة، وتوفّر خطوط `Noto Sans Arabic` و`Almarai` المحلية قراءة عربية واضحة دون اتصال بالإنترنت.
- **مقياس الخط الديناميكي (`UI Scale`):** استخدام `0.9375rem` كحجم افتراضي لحقول الإدخال والأزرار لتستجيب لتكبير/تصغير مقياس الواجهة، مع إلغاء التقطيع العربي `hyphens: none !important;` داخل `[dir="rtl"]`.

### 3.2 قواعد عرض الأرقام والمبالغ المالية
1. **الأرقام الجدولية الإلزامية:** مفعّلة عالمياً عبر:
   ```css
   * { font-variant-numeric: lining-nums tabular-nums; }
   html { font-feature-settings: "lnum" 1, "tnum" 1; }
   ```
   ويُضاف الصنف `tabular-nums` صراحةً على كل خلية مبلغ أو رصيد أو كمية أو نسبة مئوية لضمان محاذاة الأعمدة عمودياً ومنع اهتزاز العرض أثناء التحديث الحي.
2. **عزل الاتجاه (`dir="ltr"`) داخل الواجهة العربية (`RTL`):**
   - كل مبلغ مالي، إشارة سالبة/موجبة (`-15.50 $`)، رقم فاتورة (`INV-2026-001`)، باركود، رقم هاتف، أو سعر صرف يجب تغليفه بـ `dir="ltr"` مع `inline-block` أو `[unicode-bidi:isolate]`:
     ```tsx
     <span dir="ltr" className="inline-block tabular-nums font-semibold">
       {formatInCurrency(amountUsd, currency)}
     </span>
     ```
   - يُمنع ترك علامة السالب أو رمز العملة معرضين لانقلاب خوارزمية BiDi في الجمل العربية.
3. **مصدر واحد لتنسيق العملات:**
   - استخدام `formatInCurrency` و`use-money.tsx` و`MoneyInput.tsx` (`src/lib/money-engine.ts`) حصراً.
   - يُمنع كتابة `$` أو `SYP` أو `TRY` بشكل ثابت في الواجهة، ويُحافظ على عرض المكافئ بالدولار (`= X $`) عند التعامل بعملات التحصيل وفق `AGENTS.md`.

## 4. معايير التباين، أهداف اللمس، واستجابة Android وWindows

### 4.1 التباين (Contrast — WCAG AA Minimum)
- **النصوص العادية والأرقام المالية:** نسبة تباين لا تقل عن **`4.5:1`** في الوضعين الليلي والنهاري.
- **العناوين الكبيرة (`>= 18pt` أو `14pt Bold`)، الأيقونات الوظيفية، وحدود الحقول:** نسبة تباين لا تقل عن **`3:1`**.
- يُمنع استخدام نص باهت (`opacity-40` أو `text-muted-foreground/50`) للأرقام المالية أو حالات الفواتير أو أزرار الإجراءات.

### 4.2 أهداف اللمس والتفاعل (Touch Targets `>= 44px`)
- الحد الأدنى الملزم لكل زر، أيقونة، تبويب، أو عنصر نقر في Android وأجهزة الكاشير اللمسية هو **`44×44px`** (`min-h-[44px] min-w-[44px]` أو `h-11`).
- مسافة أمان بين الأزرار المتجاورة لا تقل عن **`8px` (`gap-2`)** لمنع الضغط الخاطئ أثناء ذروة البيع.
- على Windows (Electron): الحفاظ على حالات `:hover` و`:focus-visible` (`ring-2 ring-ring`) ودعم التنقل بلوحة المفاتيح (`Tab` / `Enter` / `Esc`) مع إبقاء أزرار الكاشير الرئيسية مريحة للشاشات اللمسية كذلك.

### 4.3 التخطيط المتجاوب والخصائص المنطقية (`RTL / LTR`)
- **نقاط التوقف المعتمدة (`tailwind.config.ts`):** `xs: 380px`، `mobile: <= 767px`، `ipad: 768–1023px`، `pc: >= 1024px`.
- **الخصائص المنطقية حصراً:** استخدام `ms-*`, `me-*`, `ps-*`, `pe-*`, `start-*`, `end-*`, `text-start`, `text-end` بدل `ml/mr/pl/pr/left/right` حتى ينعكس التصميم تلقائياً بين العربية (`rtl`) والإنجليزية (`ltr`).
- **مربعات الحوار (`Dialogs`):**
  - الحاوية: `w-[min(calc(100vw-1.5rem),42rem)] max-h-[calc(100dvh-1.5rem)] flex flex-col p-0 overflow-hidden`.
  - الترويسة ثابتة (`shrink-0 text-start pe-8`) وزر الإغلاق `end-3.5 top-3.5 rounded-full`.
  - التذييل: `flex flex-col-reverse sm:flex-row sm:justify-end gap-2`.
  - حماية الاستمارات من الإغلاق العرضي (`onPointerDownOutside` / `onEscapeKeyDown`) عند وجود تعديلات غير محفوظة.
- **القوائم المنسدلة (`Dropdowns`):** سقف ارتفاع `max-h-[min(20rem,60dvh)] overflow-y-auto`.
- **شبكات الإحصائيات (`KPI Grids`):** `grid-cols-2 sm:grid-cols-4` لمنع تكدس الأرقام وقصّها على الهواتف.

## 5. قاعدة منع النصوص الثابتة (Zero Hardcoded Strings & `ar.ts`/`en.ts` Parity)

1. **إلزام `t(...)` في كل واجهة:**
   - يُمنع كتابة أي نص مرئي ثابت (عربي أو إنجليزي) داخل `src/pages/` أو `src/components/` — يشمل ذلك العناوين، الأزرار، تسميات الحقول، الـ `placeholder`، رسائل التنبيه (`toast`)، حالات الفراغ، ونصوص `aria-label` و`title`.
   - يُستورد التابع `t` من `src/lib/i18n.ts` (أو الهوك المعتمد للغة) ويُستخدم بمفتاح وصفي هرمي (مثل `pos.checkout.confirm` أو `debts.status.partiallyPaid`).
2. **التطابق الصارم 1:1 بين `ar.ts` و`en.ts`:**
   - أي مفتاح يُضاف أو يُعدّل أو يُحذف في `src/lib/locales/ar.ts` يجب تحديث نظيره فوراً في `src/lib/locales/en.ts` في نفس الـ Commit.
   - يُمنع ترك قيم فارغة أو نصوص غير مترجمة أو مفاتيح يتيمة؛ لأن النوع `TranslationKey = keyof typeof ar` يعتمد على `ar.ts` كمرجع بنيوي.
3. **تنسيق المتغيرات داخل النصوص:**
   - عدم تجميع الجمل بدمج نصوص متفرقة (`text1 + " " + text2`) لأن ترتيب الكلمات يختلف بين العربية والإنجليزية؛ تُستخدم قوالب الاستبدال (`{count}`, `{amount}`) مع عزل الأرقام بـ `dir="ltr"`.
